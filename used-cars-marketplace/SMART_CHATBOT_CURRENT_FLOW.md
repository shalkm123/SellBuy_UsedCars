# Smart Chatbot: Current Flow and Car-Return Technique

This document explains how the Smart Chatbot currently works in the codebase, end-to-end.

## 1) Current Reality (Important)

The chatbot currently returns a single AI text reply.
It does **not** currently query the cars table or return a structured list like `recommendedCars`.

So when users ask for cars, recommendations are generated by Gemini as plain text based on prompt context, not live DB filtering.

## 2) Endpoint Surface

Backend mounts chatbot routes at:
- `POST /api/chatbot`
- `POST /api/chatbot/query` (alias to same handler)

Both routes require JWT auth middleware.

## 3) End-to-End Request Flow

1. User types a message in `Chatbotpage.jsx`.
2. Frontend calls `sendChatMessage(message)` from `api.js`.
3. Axios request interceptor injects `Authorization: Bearer <token>` from localStorage.
4. Request reaches `POST /api/chatbot`.
5. Route applies `verifyToken` middleware.
6. Controller validates `message` exists.
7. Controller builds a static system prompt (`CarBot` persona + India-specific constraints).
8. Controller calls `callGemini(...)` service.
9. Gemini API returns generated text.
10. Controller returns JSON `{ reply: "..." }`.
11. Frontend appends this text as a bot message bubble.

## 4) Backend Components Involved

### Route
- `backend/routes/chatbot.js`
- Wires both `/` and `/query` to same controller.
- Applies auth middleware.

### Controller
- `backend/controllers/Chatbotcontroller.js`
- Input: `req.body.message`
- Validation: `400` if message missing.
- Prompting approach:
  - fixed system context (used-cars marketplace domain)
  - user message as prompt
  - `temperature: 0.7`, `maxOutputTokens: 500`
- Output: `res.json({ reply })`

### Gemini Service
- `backend/services/gemini.js`
- Reads:
  - `GEMINI_API_KEY` (required)
  - `GEMINI_MODEL` (optional, defaults to `gemini-2.0-flash`)
- Calls Google Generative Language API `generateContent`.
- Throws errors when API key is missing, API fails, or text is empty.

## 5) Frontend Components Involved

### API client
- `frontend/src/api.js`
- `sendChatMessage(message)` -> `POST /chatbot` with `{ message }`

### UI page
- `frontend/src/pages/Chatbotpage.jsx`
- Maintains local chat state (`messages`, `typing`, input).
- Sends message, shows typing indicator, appends `res.data.reply`.
- On failure, shows fallback: `Sorry, something went wrong. Please try again.`

## 6) Request/Response Contract (Current)

### Request
```json
POST /api/chatbot
Authorization: Bearer <jwt>
Content-Type: application/json

{
  "message": "Find me a sedan under 8 lakh in Delhi"
}
```

### Success Response
```json
{
  "reply": "Gemini-generated natural language response"
}
```

### Error Responses
- `400`: message missing
- `401/403`: auth failure from middleware
- `500`: Gemini/API/server error

## 7) Technique Currently Used to "Return Cars"

Current technique is **LLM-only conversational recommendation**:
- No SQL query is run in chatbot handler.
- No ranking algorithm over `cars` rows is executed in chatbot handler.
- Any car suggestions are generated text from Gemini, using the system instruction and user query.

In short:
- "Return cars" means text suggestions right now.
- It is not yet a structured, database-backed retrieval pipeline.

## 8) What Is Not Implemented Yet (in current chatbot flow)

- Parsed filter object (budget/city/fuel/transmission) in response.
- DB search based on parsed filters.
- Structured `recommendedCars` payload with IDs for direct card rendering.
- Session persistence (`chat_sessions`, `chat_messages`) for long-term conversation memory.

## 9) Security and Operational Notes

- Chatbot is protected by JWT route guard.
- Gemini key is mandatory at runtime.
- If `GEMINI_API_KEY` is absent, chatbot returns server error from service layer.
- Frontend can only use chatbot when logged in (protected route + protected API call).

## 10) Practical Impact on UX Today

- Users get fast conversational help.
- Recommendations can be useful but are not guaranteed to map to live inventory.
- Direct "click-to-open recommended car" behavior is not available from chatbot response because response contains only text.
